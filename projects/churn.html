Customer Churn Prediction.

End-to-end churn prediction model deployed for a major Algerian telecom operator. Integrated NPS, network experience, traffic, and device signals from four operator systems into a unified gradient-boosted classifier. Outputs fed directly into precision marketing campaigns, contributing to measurable retention improvement.

Vendor
Huawei (SmartCare)
Client
Major Algerian operator
Role
Data Analytics Lead
Year
2021 – 2022

The problem

The operator was losing customers at an above-industry rate but couldn't intervene in time — by the time churn was visible in standard reporting (cancelled subscription, zero usage for 30 days), the customer had already left. They needed forward-looking churn scoring with enough lead time for marketing intervention.

Telecom churn is a multi-signal problem. No single signal is reliable on its own:

  • Usage drops happen for many reasons — vacations, illness, secondary lines.
  • NPS declines are noisy and have low coverage (only customers who respond).
  • Complaint volumes spike for individual incidents that don't lead to churn.
  • Network experience degradation matters but only relative to the customer's expectations.

Combining these signals into a reliable forward-looking score required ingesting data from multiple operator systems and engineering features that captured trends, not snapshots.

Approach

Data integration

Pulled signals from four operator systems and unified them in a Hadoop-based feature store:

  • CRM. NPS scores, complaint history, complaint-to-resolution time, plan changes.
  • CEM platform. Network experience KQIs (drop call rate, throughput, latency) per subscriber.
  • Core Network probes. Traffic patterns, session-level data, OTT app usage.
  • Billing. Plan tier, ARPU trends, payment history, top-up frequency.

Spark + Hive ETL pipeline ran weekly to refresh the feature store, with consistent subscriber-level joins across all four systems.

Feature engineering

Built rolling-window features that capture trends rather than point-in-time values — the signal that matters for churn is almost always a change, not a level:

  • 30, 60, and 90-day usage trends with delta calculations
  • NPS deltas (change in score over time, not absolute score)
  • Complaint-to-resolution ratio over rolling 60-day windows
  • Traffic volatility (standard deviation of daily usage)
  • Device upgrade signals — new device on the network is a positive engagement signal
  • Recharge pattern changes for prepaid subscribers

Model training

Gradient-boosted classifier (Python, scikit-learn) trained on labelled churn outcomes from a 12-month historical window. Hyperparameter tuning via stratified cross-validation to handle the class imbalance (churn is a rare event). Probability calibration via Platt scaling so the output scores are interpretable as actual churn probabilities — important because marketing needed to make threshold decisions ("intervene above 60% probability").

Production deployment

Daily scoring pipeline producing per-subscriber churn probability plus the top contributing factors (feature importance per prediction, via SHAP values). The contributing factors mattered as much as the score itself — they let the marketing team tailor interventions:

  • High-risk + network experience driver → technical outreach + service credit
  • High-risk + price driver → personalised plan offer
  • High-risk + competitor signal → retention package with bonus data
  • Medium-risk → engagement campaign (educational content, app push)
Identified at-risk customers 30+ days before churn became visible in lagging indicators — long enough for marketing to actually do something about it.

Outcome

Marketing team used the scores to prioritise retention spend on customers most likely to leave and most likely to be saved by intervention. Contributed to measurable retention improvement and incremental revenue.

The same data integration and feature engineering approach was extended to two adjacent models for the same client — user segmentation (behavioural clusters for marketing) and migration propensity (predicting 2G/3G users likely to upgrade to 4G when offered). Both reused the unified feature store, which amortised the original integration investment.
