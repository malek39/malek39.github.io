Mediterranean Games — Network SOC.

Real-time network quality monitoring for Mobilis (ATM Mobilis), the official technology partner of the Oran 2022 Mediterranean Games. Built BTS-level dashboards tracking voice (CS) and data (PS) performance across 3G and 4G nodes in the event geography, enabling the operator's Service Operations Center to detect and remediate network degradation while the live event was still in progress.

Client
ATM Mobilis
Vendor
Huawei (SmartCare)
Role
Lead Analytics Engineer
Event
Oran 2022 · 11 days

Press coverage: Le Soir d'Algérie — Mobilis inaugure un centre technique pour surveiller la qualité de son réseau

The problem

The Mediterranean Games are a major sporting event — 11 days of competition drawing athletes, officials, broadcasters, and spectators from across the Mediterranean basin. As the official technology partner, Mobilis carried both the network load and the brand stakes: any visible degradation at a venue or in a broadcast feed would land on the front page of national press.

Standard Customer Experience Management dashboards refresh on hourly or daily windows. Adequate for normal operations but completely insufficient for live event monitoring, where a Voice or Data degradation needs detection in minutes, not hours. By the time a daily KPI dashboard surfaces a problem, the broadcast slot is already over — and the operator's brand has already taken the hit.

The brief was: stand up a dedicated Service Operations Center (SOC) for the duration of the event, with BTS-level visibility into Voice (CS) and Data (PS) performance, refreshed fast enough that the NOC team could act on a problem before it became visible to users.

Approach

Network architecture scope

The monitoring layer covered the full radio access network for the event geography — from the radio side down to the core:

  • BTS / Node B (3G) — voice and data carried over UMTS in older coverage zones.
  • eNodeB (4G/LTE) — primary data carrier and increasingly the voice carrier via VoLTE.
  • Core Network — CS (Circuit-Switched) for legacy voice signalling; PS (Packet-Switched) for data and modern voice.

The dashboards needed to surface anomalies at the BTS / eNodeB level — the most granular unit where the NOC team can actually take action (cell reboot, load rebalancing, neighbour-list reconfiguration, escalation to radio engineering).

KPIs that matter for a live event

Voice (CS) side:

  • Drop Call Rate per cell — single best indicator of voice service quality.
  • Call Setup Success Rate — measures whether calls connect at all.
  • Paging Success Rate — proxy for network reachability.
  • Handover Success Rate — critical at venue boundaries with high user mobility.
  • Voice Quality (MOS) — perceived voice quality scoring.

Data (PS) side:

  • Throughput uplink and downlink per cell — the metric broadcasters care about.
  • Latency — RTT and one-way delay.
  • Data Session Establishment Success Rate — can users actually attach and use data?
  • Cell-level user volume and PRB utilisation — capacity headroom.
  • OTT performance — proxy KPIs for streaming apps used by spectators and broadcast crews.

Data pipeline

Built on top of the existing Huawei SmartCare platform, but with the refresh windows and aggregation layer adapted for live monitoring:

  • Raw trace data ingested from PS Probes and CS Probes at the Core Network.
  • Cell-level performance counters pulled from the radio OSS.
  • Ingestion via the Hadoop ecosystem (Spark, Hive); refresh window compressed from hourly to minute-level granularity for the event window.
  • Aggregations partitioned by venue geography — event sites, athlete villages, broadcast centres, transport corridors.

SOC dashboards designed for action

I designed the dashboards specifically for the NOC engineers who actually fix problems — not for executive observation. Each metric had a clear next action:

  • Threshold-based alerts tuned per KPI based on the cell's baseline performance.
  • Geographic overlays showing affected cells on a venue map.
  • Drill-down from venue → cell → KPI history for fast root-cause investigation.
  • Severity prioritisation by user volume and geographic concentration — a degraded cell at a venue mid-event outranks a degraded cell in an empty parking lot.

The distinction matters: a dashboard built for observation gets watched, then ignored when the pressure spikes. A dashboard built for action gets used.

Outcome

Mobilis launched the dedicated SOC for the duration of the event (covered in Le Soir d'Algérie). The NOC monitored Voice and Data performance live throughout the 11 days. Several degradations were detected and remediated within minutes — fast enough that they didn't translate into visible service quality issues at the venues or for the broadcast feeds.

The approach was extended into Mobilis's standard event-monitoring playbook: any subsequent major event (concert, religious gathering, sporting event) now triggers a live-monitoring stand-up using the same template — BTS-level KPI tracking, geographic overlays, and minute-granularity refresh on CS and PS performance.

Standard hourly dashboards are a tool for understanding what happened. Minute-granularity dashboards designed for action are a tool for fixing problems while they're still happening.
